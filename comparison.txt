Сравнение со штатным просмотром зависимостей pip

depvis.py не вызывает pip. Страницу https://pypi.org/pypi/<имя>/json она
скачивает через urllib и из поля requires_dist забирает только имена прямых
зависимостей. Обход графа, фильтр, циклы, ASCII, PlantUML и SVG — в том же файле.
Штатная проверка того же списка:

  python -m pip show <имя>
  python -m pip install <имя> --dry-run

и, если пакет уже установлен в окружении, дерево:

  python -m pipdeptree -p <имя>

Расхождения, которые остаются даже при верном разборе:

1. Версия. Этот инструмент берёт документ последней версии на PyPI.
   pip show и pipdeptree показывают версию, которая стоит в текущем
   окружении. Списки зависимостей у разных версий не совпадают.

2. Необязательные возможности. Строки с маркером extra == "..." в
   requires_dist описывают дополнительные наборы (tests, socks и другие).
   Обычная установка их не ставит, и в граф они не входят. pip show их
   тоже не относит к обязательным зависимостям базовой установки.

3. В графе только имена. Ограничения версий (>=, ==, маркеры
   python_version и sys_platform) в вершины не превращаются. pip при
   установке выбирает конкретную версию и может отбросить зависимость,
   чей маркер не выполнен на этой машине. Такой пакет может быть в графе
   и отсутствовать у pip show.

4. Обратные зависимости штатный pip по одному пакету не показывает:
   он знает, что требует выбранный пакет, а не кто требует его.
   Поэтому режим --reverse сделан для файла тестового репозитория,
   где описан весь граф.

5. Картинка SVG строится по тому же списку рёбер, что и текст PlantUML.
   Отдельный отрисовщик PlantUML может разложить блоки иначе, набор
   рёбер при этом тот же.
